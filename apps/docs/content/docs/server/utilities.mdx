---
title: "Server utilities"
description: "Use server-side helpers for stored files outside the upload flow."
---

`serverUtils` lives on your `UploadStuff` instance. Use it when your server needs to create, remove, or clean up files outside the browser presigned-upload lifecycle.

## uploadFile

Use `uploadFile` for server-initiated uploads: generated reports, imports from another system, or any file your backend already has in memory.

Pass `{ data, content }`. `data` contains the file row fields you own: `filename`, `size`, `contentType`, `isPublic`, and any required custom fields declared on the instance. Leave out the library-owned columns — `id`, `key`, `stored`, `storedAt`, `createdAt`, `batchId`, `publicUrl`, and `uploadSessionData`; UploadStuff stamps those lifecycle, timestamp, and public-URL fields itself.

```ts
const bytes = await renderReport();

await uploadStuff.serverUtils.uploadFile({
  data: {
    filename: "report.pdf",
    size: bytes.byteLength,
    contentType: "application/pdf",
    isPublic: false,
  },
  content: bytes, // string | Uint8Array; Buffer is a Uint8Array in Node
});
```

If your instance declares required custom fields, include them in `data` too:

```ts
await uploadStuff.serverUtils.uploadFile({
  data: {
    filename: "avatar.png",
    size: imageBytes.byteLength,
    contentType: "image/png",
    isPublic: true,
    userId: "user_123",
  },
  content: imageBytes,
});
```

## deleteFiles

Use `deleteFiles` when your own server action decides files should be removed. Pass database file IDs, not storage keys.

```ts
await uploadStuff.serverUtils.deleteFiles([fileId]);
```

The utility removes the storage objects first, then deletes the database rows. If storage deletion fails, the rows stay in place so you do not lose track of orphaned objects.

## cleanUpFiles

Use `cleanUpFiles` to sweep stale pending rows that are older than the instance upload window.

```ts
await uploadStuff.serverUtils.cleanUpFiles();
```

Schedule this from a cron job or queue worker instead of calling it from a request path. See [Cleanup job](/docs/guides/cleanup-job) for a scheduling pattern.
