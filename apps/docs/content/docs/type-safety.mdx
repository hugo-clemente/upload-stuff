---
title: Type safety
description: One router definition types both the server handlers and the client hook — and the compiler keeps them in sync.
---

`upload-stuff` has a single source of truth: the file router you define on the
server. The server handlers (`middleware`, `onUploadComplete`) and the client
hook (`useUploadStuff`) all read their types from it, so the two ends **cannot
drift** — change the router and every call site updates or fails to compile.

Every block on this page is type-checked at build time, so the hovers below are
the real inferred types, not hand-written annotations.

## One definition, both ends

Hover the `// ^?` lines — those types are inferred, not declared. The
`.middleware()` return flows into `.onUploadComplete()`, and the
`.onUploadComplete()` return flows to the client's `onClientUploadComplete`.

```ts twoslash
import { UploadStuff, createUploadStuffRouter } from "@upload-stuff/server";
import type {
  StorageAdapterFactory,
  DatabaseAdapterFactory,
  inferRouteServerData,
} from "@upload-stuff/server";
import { createUploadStuffClient } from "@upload-stuff/client";
import { createUploadStuffReactHelpers } from "@upload-stuff/react";
import { z } from "zod";

// `declare const` stands in for your real adapter factories — what
// `s3Adapter(...)` and `prismaAdapter(...)` return — so this whole
// sample type-checks with no runtime wiring.
declare const storageAdapter: StorageAdapterFactory;
declare const databaseAdapter: DatabaseAdapterFactory;

const uploadStuff = UploadStuff({
  storageAdapter,
  databaseAdapter,
  filePublicUrlGenerator: ({ key }) => `https://cdn.example.com/${key}`,
});

// ---- Server: one typed route ----
type Context = { userId: string };
const f = createUploadStuffRouter<typeof uploadStuff, Context>();

const fileRouter = {
  avatar: f({ isPublic: true, files: ["image/*"], maxFileSize: "4MB" })
    .input(z.object({ folderId: z.string() }))
    .middleware(({ ctx }) => ({ uploadedBy: ctx.userId }))
    .onUploadComplete(({ input, middlewareData }) => {
      // `input` and `middlewareData` are typed from .input() and .middleware().
      // Whatever you return here is sent to the client, typed:
      return { ownerId: middlewareData.uploadedBy, folder: input.folderId };
    })
    .build(),
};

export type FileRouter = typeof fileRouter;

// `middlewareData` in onUploadComplete is exactly the middleware's return:
type MiddlewareData = FileRouter["avatar"]["$types"]["middlewareData"];
//   ^?

// ---- Client: the hook infers everything from `FileRouter` ----
const client = createUploadStuffClient<FileRouter>({
  baseURL: "https://example.com",
});
const { useUploadStuff } = createUploadStuffReactHelpers(client);

useUploadStuff((r) => r.avatar, {
  onClientUploadComplete: (res) => {
    // No annotation — `res.serverData` is the onUploadComplete return:
    console.log(res.serverData.ownerId);
  },
});

// The client payload type is derived from the server route:
type ClientPayload = inferRouteServerData<FileRouter["avatar"]>;
//   ^?
```

The `(r) => r.avatar` selector is more than a string: because the route name is a
real property, `Go to Definition` on it jumps straight to the route's server
definition.

## What the compiler rejects

Because both ends share one definition, the mistakes that would normally surface
at runtime become compile errors instead. These two fail to build:

```ts twoslash
// @errors: 2339 2551
import { UploadStuff, createUploadStuffRouter } from "@upload-stuff/server";
import type { StorageAdapterFactory, DatabaseAdapterFactory } from "@upload-stuff/server";
import { createUploadStuffClient } from "@upload-stuff/client";
import { createUploadStuffReactHelpers } from "@upload-stuff/react";

declare const storageAdapter: StorageAdapterFactory;
declare const databaseAdapter: DatabaseAdapterFactory;

const uploadStuff = UploadStuff({
  storageAdapter,
  databaseAdapter,
  filePublicUrlGenerator: ({ key }) => `https://cdn.example.com/${key}`,
});

type Context = { userId: string };
const f = createUploadStuffRouter<typeof uploadStuff, Context>();

const fileRouter = {
  avatar: f({ isPublic: true, files: ["image/*"], maxFileSize: "4MB" })
    .middleware(({ ctx }) => ({ uploadedBy: ctx.userId }))
    .onUploadComplete(({ middlewareData }) => {
      // `.middleware()` returned `{ uploadedBy }`, so `.role` does not exist:
      return { role: middlewareData.role };
    })
    .build(),
};

const client = createUploadStuffClient<typeof fileRouter>({
  baseURL: "https://example.com",
});
const { useUploadStuff } = createUploadStuffReactHelpers(client);

// Misspelled route name — the selector is type-checked against the router:
useUploadStuff((r) => r.avatr);
```

> One ordering rule: each builder method reads the *current* type, so write the
> chain as `.input().middleware().onUploadComplete().build()`. Calling
> `.onUploadComplete()` before `.middleware()` would leave `middlewareData`
> unset.
